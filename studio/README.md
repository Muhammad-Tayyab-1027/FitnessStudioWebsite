# FitLife AI Studio

The FitLife Gym website plus an AI Studio for making gym promos, class
teasers, trainer portraits and posters with Higgsfield image and video
models. Built on the Higgsfield Studio template (Next.js, Tailwind, shadcn).

One server hosts both:

| URL          | What                                                         |
| ------------ | ------------------------------------------------------------ |
| `/`          | The FitLife static site (`../index.html` and friends)        |
| `/studio`    | FitLife AI Studio                                            |
| `/api/upload`| Signed reference-upload URLs (server side, uses the saved key) |

The static pages at the repository root stay the source of truth;
`scripts/sync-site.mjs` copies them into `public/` on every `dev`/`build`
(the copies are git-ignored). Restart `pnpm dev` after editing them.

## Run it

```sh
cd studio
pnpm install
cp .env.example .env.local   # HF_API_BASE_URL=https://api.higgsfield.ai
pnpm dev                     # http://localhost:3000, "AI Studio" in the nav
```

In the studio, click **Connect API key** in the sidebar and paste the key
copied from https://open.higgsfield.ai/api-keys as-is. A server action stores
it in an HTTP-only cookie for that browser; it never reaches client code or
logs. Use **Manage API key** to **Replace API key** or **Remove API key**.
**API key saved** only means a key is stored; the first generation proves it
is valid.

## Environment

| Variable          | Purpose                                                   |
| ----------------- | --------------------------------------------------------- |
| `HF_API_BASE_URL` | Server-only platform base, `https://api.higgsfield.ai`    |

No shared `HF_API_KEY` is used: every visitor brings their own key.

## How generation works

- Submit, poll and cancel are server actions in `generation/actions.ts`
  calling `POST /<model-path>`, `GET /requests/<id>/status` and
  `POST /requests/<id>/cancel` with `Authorization: Key <api-key>`.
- Failures come back as values (missing key, rejected key, rate limit,
  unreachable) so they stay readable in production builds; a missing or
  rejected key reopens the key dialog.
- Duplicate submits are blocked in the dock while a submit is in flight, and
  identical submissions within 10 s share one platform request on the server
  (`generation/submit-guard.ts`, process-local). A submit that times out is
  never resent automatically.
- Polling batches every running request, backs off up to 30 s on rate limits
  and outages, and gives up after 15 minutes. Failed, filtered and canceled
  runs stay in the feed.
- History and projects are browser-local (IndexedDB). There are no webhooks:
  nothing runs in the background without an open studio tab.

## Models

All 28 bundled model files (38 picker entries: 8 image, 30 video) are
installed in `generation/catalog/models/`. The barrel
`generation/catalog/models.generated.ts` is regenerated by
`scripts/sync-models.mjs`; do not edit it by hand.
